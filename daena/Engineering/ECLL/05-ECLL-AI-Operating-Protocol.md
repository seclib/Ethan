# ECLL — AI Operating Protocol

## 1. Objectif

Définir le comportement attendu d'un agent IA utilisant la documentation ETHAN.

## 2. Protocole obligatoire

Avant une modification technique significative :

1. Consulter les connaissances et expériences pertinentes.
2. Rechercher les tentatives similaires.
3. Lire résultats et causes.
4. Vérifier si conditions actuelles sont différentes.
5. Déterminer si une ancienne solution est applicable.
6. Justifier toute nouvelle tentative.
7. Définir des critères de réussite mesurables.
8. Exécuter dans les limites d'autorisation.
9. Vérifier les résultats.
10. Documenter l'expérience et capitaliser.

## 3. Règles de discours

- « Nous avons déjà essayé cette solution. Elle avait échoué pour cette raison. Depuis, les conditions suivantes ont changé. Je propose donc une autre approche, avec ces critères de validation. »
- Si aucune expérience pertinente n'est trouvée, le dire explicitement.
- Si preuves insuffisantes, ne pas présenter une conclusion comme certaine.
- Citer l'identifiant de l'expérience pertinente et son document source.

## 4. Exemple naturel

« Nous avons déjà tenté un rebuild API pour intégrer le catalog. L'API live n'exposait pas les routes car l'image était ancienne. La nouvelle image reconstruite et le mont montage du dépôt source ont changé. Je propose de conserver les mêmes routes et de vérifier l'OpenAPI live. »
